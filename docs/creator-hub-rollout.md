# Creator application and Hub rollout

The new onboarding path is separate from direct roster invitations and existing Ticket Tool chats.

1. A brand application link requires Discord `identify` login. The submitted Discord ID is derived from OAuth, not typed by the applicant. Name, email, phone, TikTok handle, last-30-day GMV, deal preference, and answers enter the assigned manager's review queue.
2. A manager's approval and the Creator Hub enrollment snapshot commit together. The brand must have at least one required, published Hub item. A decline records the decision without creating an enrollment. Decision email has its own delivery status and can be retried.
3. An enabled Discord destination passes a strict preflight: exact tenant/brand/guild binding, bot permissions and role hierarchy, accessible `#start-here`, and no other channel visible to `@everyone`. Tempo creates a one-use invite for the approval email. The operator must still verify other bots do not assign extra roles to new members on join.
4. A creator signs in to the Hub with the same Discord ID. Each enrollment holds the exact published content version and required/optional setting assigned at approval. Acknowledgment acceptance is recorded with a timestamp and immutable version ID. Marking other content complete is a creator attestation; Tempo does not currently prove a video was watched or a link was read.
5. Only a completed required-item gate allows the bot worker to add the configured Creator role and create a private coaching chat. The worker uses a lease, persists each Discord effect, and recovers a chat by its enrollment marker after a retry. Existing Ticket Tool channels are untouched.

V1 is restricted in both app code and the database to the verified Creators Corner JiYu tenant, brand, and guild IDs. Additional brands require an explicit reviewed binding rather than relying on a matching slug. The draft requires an additive Supabase migration before the preview can load its new Hub queries. Discord OAuth also requires `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_APPLICATION_REDIRECT_URI` registered for the exact host, and a 32-character `APPLICATION_DISCORD_COOKIE_SECRET`. Invite and role operations require `DISCORD_BOT_TOKEN`; decision email requires `RESEND_API_KEY` and a verified `RESEND_FROM_EMAIL`. Do not enable a brand until its actual guild, channel, category, and role choices pass the settings preflight. New brand destinations default disabled.

The owner/admin configuration is under Onboarding. Managers can publish per-brand Hub items. A brand's assigned manager alone can approve applications. The public Hub and completion endpoint recheck the form-bound Discord session, approved application, and brand/tenant IDs server-side. Hub tables and RPCs have no anon or authenticated direct grants.
